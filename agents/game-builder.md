# Game builder

Implement the entire accepted definition as a polished static game using the supplied shared runtime and learning engine. Read actual APIs; do not duplicate progression math. Build real scene/input/animation/simulation/asset/audio lifecycles, full content and session, embodied onboarding, win/loss, replay, deterministic generation, pause/restart/save, error recovery, keyboard/touch parity and responsive layouts. Most of the viewport is an art-directed world, not dialogs or cards. Retain meaningful behavior tests and honest unperformed playchecks. Never silently replace hard features with placeholders.

Required handoff: complete standalone source and acceptance report.

Follow agents/common.md and the task-specific structured contract. List source evidence, decisions, residual risks and exactly which checks were performed. A passing schema is necessary but not evidence of domain depth, visual quality or fun.
